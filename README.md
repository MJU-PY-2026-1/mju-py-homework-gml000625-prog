🛠️ Troubleshooting & 기술 회고

문제 1 : 주제가 너무 어려워질 가능성

원인: 처음에는 반도체 전공과 연결하려는 생각이 커서 실제 공정 분석처럼 복잡한 프로그램으로 가려는 방향이 있었음.
해결: 웨이퍼 결함을 복잡하게 해석하는 대신 결함 정보를 입력하고 상태를 판정하는 관리 시스템 형태로 단순화함. 전공성과 과제 난이도를 모두 맞출 수 있도록 조정함.

문제 2 : 1차 과제에 비해 기능이 과도하게 많아질 위험

원인: 처음부터 메뉴, 검색, 통계, 저장 기능까지 한 번에 넣으려 하면 코드가 길어지고 1차 과제 핵심 문법이 흐려질 수 있었음.
해결: 기능을 1차, 2차, 3차, 4차로 나누어 단계적으로 발전시키는 구조로 정리함. 1차는 입력과 조건문 중심으로 제한하고 이후 단계에서 리스트, 메뉴, 함수, 딕셔너리를 추가하기로 함.

문제 3 : 변수 이름이 모호하면 코드 이해가 어려움

원인: 짧고 단순한 변수명을 사용하면 나중에 코드가 길어질수록 의미 파악이 어려워짐.
해결: wafer_id, defect_count, defect_area, defect_location, total_score, grade처럼 의미가 분명한 변수명으로 다시 설계함. 가독성과 확장성을 함께 확보함.

문제 4 : 자료형 구분이 명확하지 않으면 계산이 불편함

원인: 입력값을 모두 문자열로 처리하면 결함 개수나 결함 면적을 계산할 때 형변환 문제가 생길 수 있음.
해결: 문자열, 정수, 실수, 논리형을 구분해서 설계함. 입력값의 역할에 따라 자료형을 명확히 나누어 계산과 판정이 자연스럽게 이루어지도록 함.

문제 5 : 결함 점수 계산식이 너무 복잡해질 수 있음

원인: 실제 반도체 공정처럼 복잡한 가중치 계산식을 넣으면 초급 파이썬 과제 수준에서 구현과 설명이 어려워짐.
해결: 결함 개수, 결함 면적, 결함 위치를 각각 점수화한 뒤 합산하는 단순한 방식으로 변경함. 조건문으로 구현하기 쉽고 결과 설명도 쉬운 구조로 정리함.

문제 6 : 프로그램이 계산기처럼 보일 수 있음

원인: 웨이퍼 1개만 입력받고 결과를 출력한 뒤 종료되는 구조는 관리 시스템보다는 단순 계산기 느낌이 강함.
해결: 여러 웨이퍼 정보를 리스트에 저장하고 메뉴를 통해 등록, 조회, 분석, 검색이 가능하도록 확장 방향을 설계함. 이를 통해 데이터 관리 시스템처럼 보이도록 개선함.

문제 7 : 저장 구조를 어떻게 잡을지 애매했음

원인: 웨이퍼 하나에 여러 정보가 들어가므로 어떤 방식으로 저장해야 나중에 출력과 검색이 쉬울지 고민이 있었음.
해결: 초기에는 같은 순서의 리스트 여러 개를 사용하는 방식으로 단순화하고 최종 단계에서는 리스트 안에 딕셔너리를 저장하는 방향으로 확장하기로 정리함. 초급 수준과 확장성을 모두 고려한 선택이었음.

    print(f"\n[{i+1}번째 웨이퍼 입력]")

    #1. 입력
    wafer_id = input("웨이퍼 번호: ")
    process_name = input("공정명:")
    defect_count = int(input("결함 개수: "))
    defect_area = float(input("결함 면적: "))
    defect_location = input("결함위치 center/ edge/ other): ")

    #2. 점수 계산
    count_score = defect_count * 10

    if defect_area < 10:
        area_score = 10
    elif defect_area < 50 :
        area_score = 30
    else :
        area_score = 60

    if defect_location == "center" :
        location_score = 50
    elif defect_location == "edge" :
        location_score = 30
    else:
        location_score = 10

    total_score = count_score + area_score + location_score

    #3. 상태 판정
    if defect_count >= 10 and defect_location == "center" :
        grade = "긴급위험"

    elif defect_area > 80 or defect_location == "center" :

## 🟩 [2차 과제: V1.0] 입출력 + 리스트 + 조건문 - 향후 작성 예정
### **✨2차 과제 내용:**
본 프로그램은 웨이퍼 결함 정보를 입력받아 간단한 점수 계산과 상태 판정을 수행하는 콘솔 기반 시스템이다. 사용자는 결함 개수, 결함 면적, 결함 위치 등의 데이터를 입력하며, 입력된 값은 리스트에 저장되어 여러 개의 웨이퍼 정보를 관리할 수 있다. 각 데이터는 input()으로 입력되며, 계산을 위해 정수 또는 실수로 형변환을 수행한다.
저장된 데이터는 간단한 공식으로 결함 점수를 계산하고, if-elif-else 조건문을 통해 정상, 주의, 위험 상태로 분류된다. 또한 and, or 논리연산자를 활용하여 특정 조건을 만족할 경우 추가적인 특별 판정을 수행하도록 설계하였다.
전체 구조는 입력 → 리스트 저장 → 점수 계산 → 조건 판정 → 출력의 흐름으로 구성되어 있으며, 반복문(for)을 통해 여러 데이터를 처리할 수 있도록 확장 가능한 형태로 설계하였다. 이는 리스트와 조건문을 결합한 기본적인 데이터 처리 프로그램 구조를 이해하는 것을 목표로 한다.
### **🤖 AI 파트너십 과정**
내용 1: 리스트 입력 구조 설계
프롬프트 요약: 여러 웨이퍼 정보를 입력받아 리스트에 저장하는 코드 구조 요청
적용 내용: for문 + append() 구조로 반복 입력 및 저장 구현
이해 및 개선: 반복문을 사용하면 동일 코드를 여러 번 작성할 필요 없이 자동 처리된다는 점 이해

내용 2: 결함 점수 계산식 설계
프롬프트 요약: 결함 개수, 면적, 위치 기반의 간단한 점수 공식 요청
적용 내용: 단순 가중치 기반 점수 계산식 설계 (초급 수준 유지)
이해 및 개선: 너무 복잡한 공식보다 “조건문으로 처리 가능한 단순 구조”가 중요함을 학습

내용 3: 조건문 등급 판정 로직
프롬프트 요약: 점수 기준으로 상태 분류 + 논리연산 포함 조건문 요청
적용 내용: if-elif-else로 정상/주의/위험 구분 + and/or로 특별 조건 추가
이해 및 개선: 조건문은 위에서부터 순서대로 실행된다는 구조를 명확히 이해

내용 4: 리스트 전체 출력 구조
프롬프트 요약: 저장된 여러 데이터를 반복문으로 출력 요청

핵심 교훈:
파이썬 코드는 위에서 아래로 실행되므로 함수는 먼저 정의하고 나중에 호출해야 한다.

문제 5 : 전역변수 값이 함수 안에서 증가하지 않는 문제
원인:
함수 안에서 전역변수 wafer_count 값을 수정하면서 global wafer_count를 작성하지 않으면 파이썬이 이를 지역변수로 처리할 수 있다.
해결:
웨이퍼 등록 함수 안에 global wafer_count를 작성한 뒤 wafer_count += 1을 실행하도록 수정하였다.
핵심 교훈:
함수 안에서 전역변수 값을 수정하려면 global 키워드가 필요하다.

문제 6 : return과 print를 혼동하는 문제
원인:
계산 함수에서 print()만 사용하면 화면에는 출력되지만 계산 결과를 다른 함수나 변수에서 다시 사용할 수 없다.
해결:
결함 점수 계산 함수에서는 return total_score를 사용하고, 상태 판정 함수에서는 return grade를 사용하여 결과값을 밖으로 돌려주도록 수정하였다.
핵심 교훈:
print()는 화면 출력이고, return은 함수 결과를 다시 사용하는 기능이다.

문제 7 : 조건문과 반복문에서 SyntaxError가 발생하는 문제
원인:
if, elif, else, while, def 뒤에 콜론 :을 빠뜨리거나 들여쓰기를 맞추지 않으면 문법 오류가 발생한다.
해결:
모든 조건문, 반복문, 함수 정의 끝에 콜론을 붙이고, 실행 블록은 일정하게 들여쓰기 하도록 수정하였다.
핵심 교훈:
파이썬 제어문은 콜론 + 들여쓰기 구조가 필수이다.

### **🛠️ Troubleshooting & 기술 회고:**
  1. 문제 1: 여러 웨이퍼 정보가 누적되지 않는 문제
원인: 새로운 웨이퍼를 입력할 때마다 같은 변수에 값만 다시 저장하면 이전 웨이퍼 정보가 사라짐.
해결: 웨이퍼 한 개의 정보를 리스트로 만든 뒤 wafer_list.append(wafer)를 사용하여 전체 리스트에 계속 추가함.
기술 회고: 여러 데이터를 관리할 때는 각 데이터를 하나의 리스트로 묶고 전체 리스트에 누적해야 한다는 점을 이해함.

문제 2: 숫자 입력란에 문자를 입력하면 프로그램이 종료되는 문제
원인: 결함 개수와 결함 면적을 int()와 float()로 변환하는 과정에서 숫자가 아닌 문자를 입력하면 ValueError가 발생함.
해결: 웨이퍼 입력 부분을 try-except로 감싸고, except ValueError에서 숫자를 입력하라는 안내 메시지를 출력하도록 수정함.
기술 회고: 사용자가 잘못된 값을 입력할 가능성을 고려하여 프로그램을 작성해야 한다는 점을 배움.

문제 3: 저장된 파일이 없을 때 오류가 발생하는 문제
원인: 파일을 저장하지 않은 상태에서 불러오기 기능을 실행하면 wafer_data.txt 파일이 존재하지 않아 FileNotFoundError가 발생함.
해결: except FileNotFoundError를 추가하여 파일이 없다는 안내 메시지를 출력하고 프로그램이 계속 실행되도록 수정함.
기술 회고: 외부 파일을 사용하는 프로그램은 파일이 존재하지 않는 상황을 반드시 처리해야 함을 이해함.

문제 4: 파일에서 불러온 숫자가 계산에 사용되지 않는 문제
원인: 텍스트 파일에서 읽어온 값은 모두 문자열이므로 결함 개수와 결함 면적을 그대로 계산에 사용할 수 없었음.
해결: 결함 개수와 점수는 int(), 결함 면적은 float()로 변환하여 원래의 자료형으로 복원함.
기술 회고: input()뿐만 아니라 파일에서 읽은 데이터도 필요한 자료형으로 변환해야 한다는 점을 이해함.

문제 5: 파일을 여러 번 불러오면 같은 데이터가 중복되는 문제
원인: 기존 wafer_list에 파일 데이터를 계속 추가하면 불러오기를 실행할 때마다 동일한 웨이퍼 정보가 반복해서 저장될 수 있음.
해결: 파일 데이터를 새로운 loaded_list에 먼저 저장한 후, 불러오기가 끝나면 기존 전체 리스트를 새 리스트로 교체함.
기술 회고: 파일을 불러올 때 기존 데이터에 추가할 것인지 새로운 데이터로 교체할 것인지 미리 결정해야 한다는 점을 배움.

문제 6: 이중 리스트의 숫자 인덱스가 이해하기 어려운 문제
원인: wafer[0], wafer[1]과 같은 인덱스만 보면 각각 어떤 정보를 의미하는지 바로 알기 어려웠음.
해결: 웨이퍼 번호, 공정명, 결함 개수 등의 이름을 저장한 labels 리스트를 만들고, 중첩 for문으로 항목 이름과 값을 함께 출력함.
기술 회고: 리스트를 사용할 때는 각 데이터의 저장 순서를 일정하게 유지하고 항목 이름을 함께 관리하는 것이 중요함을 배움.
